### 1. 역할·주소 구조 개편
- 역할 4개: 사장(OWNER) / 매장 직원(STORE) / 창고 직원(WAREHOUSE) / 출고 직원(FULFILLMENT)
- 관리자 주소를 `/api/admin/**`, 화면을 `/admin/**`로 분리 (나중에 쇼핑몰 `/shop/**`과 보안 설정을 따로 두기 위해)
- 직원 계정에 **담당 위치**(`location_id`) 추가 → 매장·창고 직원은 자기 위치 데이터만 처리
- 개인용/포폴용 차이는 **기능 스위치**(`app.features.*`)로 처리하고 `/auth/me`로 화면에 전달 (예: 판매사이트 메뉴는 개인용만)
- 화면에서 버튼을 숨기는 것과 별개로 **서버에서도 권한 확인** (원가는 API 응답에서도 제외: `@JsonInclude(NON_NULL)`)

### 2. QueryDSL
- 실무 조합: **JPA(기본 CRUD) + QueryDSL(조건이 바뀌는 검색)**
- OpenFeign 포크(`io.github.openfeign.querydsl`) 사용 → 빌드할 때 엔티티마다 Q클래스 자동 생성
- `BooleanBuilder`로 비어 있는 검색 조건은 무시 (상품: 검색어·시리즈·종류·구분 / 발주: 상태·공급처)
- `fetchJoin()`으로 목록 조회 시 연관 엔티티를 한 번에 가져옴
- `default_batch_fetch_size: 100` 설정 → 컬렉션을 IN 쿼리로 묶어서 조회 (N+1 방지)

### 3. 기준정보 + 공통 화면
- 창고·매장, 상품종류(계층), 공급처, 판매사이트, 배송방법(+ 상품종류별 배송비 규칙) API
- `BaseRepository.getOrThrow()`: 없으면 404를 던지는 조회를 한 곳에
- 프론트 `CrudPage`: "목록 + 등록/수정 창" 화면을 설정만으로 생성

### 4. 상품 + 위치별 재고 (핵심)
- 상품 정보(`products`)와 **위치별 재고**(`product_stocks`: 보유·예약·최소 수량)를 분리
- **재고 원장**(`stock_movements`): 모든 재고 변동을 추가만 하는 기록 (공장 입고, 매장 출고/입고, 판매, 반품, 조정 …)
- **재고 변경 단일 진입점** `StockService.change()`: 수량 변경 + 원장 기록을 한 트랜잭션으로
- **낙관적 잠금** `@Version`: 두 사람이 같은 재고를 동시에 바꾸면 늦은 쪽 실패 → `OptimisticLockingFailureException`을 409로 변환
- 재고 규칙: 보유 수량은 **주문 예약 수량 밑으로 못 내려감** (예약된 물건 보호)
- 상품 화면: **창고(온라인)/매장(오프라인) 필터로 표 2개**, 권한별로 볼 수 있는 위치만 서버에서 내려줌
- 재고 조정(사유: 실사 차이·파손·불량·분실·이동 차이), 최소 재고 설정, 변동 이력

### 5. 공장 발주·입고
- 흐름: `공장 확인 대기 → 공장 확인(확정 납기일) → 일부 입고 → 입고 완료`, 취소
- 공장은 외부 회사라 시스템을 안 씀 → **발주서 엑셀**을 보내고 회신받은 납기일을 직원이 입력
- 입고는 여러 번 나눠서 가능, 정상 수량만 창고 재고(`PRODUCTION_IN`), 불량은 기록만
- 입고 수량 잘못 입력 시 **수정 기능**: 원장은 지우지 않고 정정 기록을 추가
- 상태 자동 변경은 엔티티 메서드(`refreshStatus()`)에 둠

### 6. 재고 이동 (창고 → 매장)
- 실무 흐름: `요청(매장) → 승인/반려(창고, 사유) → 출고(창고 재고 차감) → 도착 확인(매장 재고 증가)`
- 매장 출고는 **박스 단위**: 수량 = 박스 수 × 상품 박스 입수량 + 낱개
- [부족 상품 불러오기]: 매장 최소 재고 이하 상품 자동 추가 (실무의 자동 보충 제안)
- 받은 수량이 다르면 재고 조정 '이동 수량 차이'로 수기 처리

### 7. 매장 판매 (POS) + 바코드
- 계산(POS) 화면과 판매 내역 화면을 분리 (원래는 계산대 화면은 따로 둠)
- 영수증 저장 즉시 매장 재고 차감(`SALE_OUT`), 영수증 번호 `R + 날짜 + 순번`
- **판매 시점 원가·판매가 스냅샷** → 상품 가격이 바뀌어도 지난 영수증 이익은 그대로
- 바코드 스캐너 = 키보드처럼 빠르게 입력 + Enter → 글자 간격(30ms 미만)으로 사람 입력과 구분하는 훅 `useBarcodeScanner`
- 상품 `barcode` 컬럼 + 바코드 조회 API(바코드 → 없으면 상품번호)
- **JsBarcode**로 라벨 인쇄 (13자리 숫자면 EAN-13, 그 외 CODE128)

### 8. 증정 규칙 · 포장재
- 증정은 **상품종류 기준**: 금액 구간별 증정 개수 + 대상 상품종류, 실제 상품은 주문 처리 때 직원이 선택
- 특전은 증정품 화면에서 등록·관리, 상품 화면은 재고품만
- 노션식 다중 선택 컴포넌트(`MultiSelect`): 칸 안에서 검색 → 태그로 표시
- 포장재: 위치별 재고, 등록 시 초기 수량, [입고](`PURCHASE_IN`), 사용수량(원장 `PACKAGING_OUT` 합계를 JPQL `group by`로 집계)

### 9. Apache POI 엑셀
- 실무 스프링에서 "엑셀 다운로드"는 대부분 **서버에서 Apache POI**로 생성
- 발주서 엑셀: 제목 병합, 테두리, 천 단위 서식, 단가·금액은 사장일 때만, 확정 납기일 회신칸
- `ResponseEntity<byte[]>` + `Content-Disposition`(한글 파일명은 UTF-8 지정)
- 프론트는 `responseType: 'blob'`으로 받아서 저장하는 `download()` 공통 함수

### 10. 코드 축약 · 엔티티 설계
- 엔티티 필드는 어노테이션과 한 줄로, `LAZY`·`STRING`·`IDENTITY` static import
- 같은 모양의 재고 엔티티(상품·포장재)는 `@MappedSuperclass` 상위 클래스(`LocationStock`)로
- 현재 관리자 조회는 `adminRepo.current()` 하나로, 등록·수정은 `fill()` 하나로
- 프론트 공통 부품: `useGet(url, params)`(조회), `FormModal`(등록·수정 창)
- 엔티티 수정 방식: setter를 열지 않고 의도가 드러나는 메서드(`update`, `cancel`, `ship`)로만 변경
  - **도메인 모델 패턴** + **JPA 변경 감지** (반대는 getter/setter만 있는 빈약한 도메인 모델)

### 🔧 해결한 에러

**1. 로그인 후 화면 깨짐 (`AppLayout.tsx`)**
- 원인: 서버 재시작 전이라 `/auth/me` 응답에 `features`가 없는데 `me.features[...]`를 읽음
- 해결: `me.features?.[m.feature]` 옵셔널 체이닝

**2. `import { ProductStockTable } from './ProductsPage'` IDE 오류 / ESLint Fast Refresh 경고**
- 원인: 화면 파일(pages)끼리 import, 컴포넌트 파일에서 상수·함수도 같이 export
- 해결: 공통 표는 `components/`, 상수·타입은 `lib/`로 분리

**3. `@SuperBuilder` 사용 시 `cannot find symbol`**
- 원인: `@SuperBuilder`는 부모 클래스(`BaseEntity`)에도 있어야 함
- 해결: `BaseEntity`에 `@SuperBuilder` + `@NoArgsConstructor` 추가

**4. 상태값을 추가하면 저장 시 DB 오류 (MySQL ENUM)**
- 원인: `@Enumerated(STRING)`이 MySQL `ENUM` 컬럼으로 생성되고, `ddl-auto: update`는 컬럼 정의를 안 바꿈
- 해결: `columnDefinition = "varchar(30)"` + 기존 테이블은 `ALTER TABLE ... MODIFY ... VARCHAR` 한 번 실행

**5. Workbench `1046 No database selected` / `1091 Can't DROP 'requested_at'`**
- 원인: 기본 DB 미선택 / 지우려던 컬럼이 원래 없음
- 해결: `goods.테이블`처럼 DB 이름 붙이기, `SHOW COLUMNS`로 먼저 확인

**6. 수정·입고 후 상세 화면이 새로고침되지 않음**
- 원인: React Query 키 `['/production-orders/1']`가 `invalidateQueries(['/production-orders'])`와 불일치
- 해결: `useGet`이 주소를 조각으로 나눠 키 생성 → `['/production-orders', '1']`

**7. 기본 테스트(`contextLoads`)가 실제 DB에 접속**
- 원인: `@SpringBootTest`는 앱 전체를 띄워 `.env`의 DB에 붙고 테이블까지 만듦
- 해결: 평소에는 DB 없는 엔티티 단위 테스트만 실행

**8. 화면 설계 수정함**
- 증정품: 상품처럼 하나씩 등록 → **상품종류 기준 증정 규칙** + 특전 재고 표
- 재고 표: 권한 범위로만 구분 → **창고/매장 필터로 표 2개**, 중복 컬럼(합계·박스 환산) 제거
- 매장 판매: 목록의 등록 창 → **계산(POS) 화면 분리**, 할인 제거, 바코드 스캔은 검색과 별도
- 발주서: PDF → 작은 회사에서 흔한 **엑셀(Apache POI)**

**9. 빠진 기능·단계 추가**
- 포장재 수량 입력 없음 → 등록 시 초기 수량, [입고], 재고수량·사용수량
- 확인·승인 단계 없음 → 공장 확인(확정 납기일), 매장 요청 승인·반려(사유)
- 입고 수량 수정, 최소 재고 입력, 공급처(창고 직원)·창고 재고 조회(매장 직원) 권한

**10. 코드 실수**
- `requestedAt`이 `createdAt`과 중복 → 필드 제거
- 축약 스크립트가 필드 2개를 한 줄로 붙이고 들여쓰기를 틀어지게 함 → 찾아서 수정 (일괄 변환 후 결과 확인 필수)

**11. 엑셀 버튼이 안 보임**
- 원인: 버튼이 발주 **행마다** 붙는데 발주가 0건 (코드 문제 아님)
- 교훈: 데이터 유무 → 개발 서버가 새 코드를 주는지(`curl`) 순서로 확인
