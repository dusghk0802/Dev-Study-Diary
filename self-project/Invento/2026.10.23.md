### 1. 프로젝트 초기 세팅
- Spring Boot 4.0.8 / Java 21 / Gradle 프로젝트 생성 (`Invento/backend`)
- MySQL 8에 DB 2개 생성: `goods`(개인용), `stationery`(포트폴리오 데모용) + 앱 전용 계정 `invento_app`
- `application.yml`에서 DB 이름을 프로필로 전환 (`demo` 프로필 → `stationery`)
- DB 비밀번호 등 민감 정보는 `.env`로 분리하고 Git에서 제외
- Git 저장소 생성 후 GitHub(Public) 연동

### 2. 설계 결정
- **워크스페이스 제거**: 데모/개인 데이터를 DB 자체로 분리했기 때문에 `workspace_id` 기반 분리가 불필요
- **Flyway 대신 엔티티로 테이블 생성** (`ddl-auto: update`)
  - `update`는 컬럼 추가만 하고, 이름 변경·삭제는 반영하지 않는다는 점을 알게 됨
- **JPA 선택 이유**: CRUD 위주 기능, 재고·주문을 한 트랜잭션에서 처리하기 편함. 복잡한 검색은 나중에 QueryDSL로 보완
- **패키지 구조**: `domain`(기능별) / `global`(공통 설정·예외) 으로 분리
- **컬럼 네이밍 규칙**: `use_yn` 같은 `_yn` 대신 `active`, `visible` 같은 boolean 이름 사용
  - 삭제·읽음 여부는 플래그 대신 시각 컬럼 하나로 표현 (`deleted_at`, `read_at`)
  - boolean은 `preferred_boolean_jdbc_type: TINYINT` 설정으로 DB에 0/1 저장
- 포트폴리오 데모 데이터는 **문구 가상 데이터**로 결정 (실제 브랜드·이미지는 상표/저작권 문제)

### 3. 공통 구조
- `JpaConfig` (`@EnableJpaAuditing`): 생성일·수정일 자동 기록 기능 활성화
- `BaseEntity` (`@MappedSuperclass`): 모든 엔티티가 상속받는 `created_at`, `updated_at`
- 공통 예외 처리
  - `ErrorCode`(enum): 오류마다 HTTP 상태 + 메시지를 한 곳에서 관리
  - `BusinessException`: 스프링 내장 `ErrorResponseException`을 상속 → 별도 핸들러 없이 표준 JSON(ProblemDetail)으로 응답
  - `spring.mvc.problemdetails.enabled: true`

### 4. 시리즈 기능 (첫 엔티티)
- `Series` 엔티티 + `SeriesRepository` (메서드 이름으로 쿼리 생성: `existsBySeriesName`)
- DTO 분리 이유: 받을 값/보낼 값만 정의, 입력 검증(`@NotBlank`, `@Size`)을 DTO에 둠
- `SeriesRequest`, `SeriesActiveRequest`(`Boolean` + `@NotNull`로 값 누락 방지)

### 🔧 해결한 에러

**1. MySQL Workbench 접속 시 `Access denied for user 'root'@'localhost'`**
- 원인: Workbench Vault에 예전 프로젝트의 root 비밀번호가 저장돼 있어서, 새 비밀번호를 묻지 않고 예전 값으로 접속
- 해결: 접속 설정의 Password → **Clear**로 저장된 비밀번호를 지우고 다시 입력

**2. `use_yn` 컬럼 타입이 의도(`char(1)`)와 다르게 `varchar(1)`로 생성**
- 원인: Hibernate `YesNoConverter`는 길이 1의 문자열로 매핑해서 MySQL에 `varchar(1)`을 만듦
- 해결: 결국 `_yn` 방식을 버리고 `boolean` + `TINYINT` 설정으로 변경

**3. 엔티티의 컬럼 이름을 바꿨는데 DB에 반영되지 않음 (`use_yn` → `active`)**
- 원인: `ddl-auto: update`는 컬럼 이름 변경·삭제를 처리하지 않음 (새 컬럼만 추가, 옛 컬럼은 그대로 남음)
- 해결: 데이터가 없는 상태라 `DROP TABLE` 후 앱을 다시 실행해서 테이블 재생성
- 교훈: `update` 사용 시 구조 변경 후에는 `DESC 테이블명`으로 꼭 확인
