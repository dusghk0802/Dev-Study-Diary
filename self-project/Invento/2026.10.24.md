### 1. 시리즈 CRUD 완성
- `SeriesService`: 이름 중복 검사(409), 없는 ID(404), 이름 앞뒤 공백 제거
  - JPA **변경 감지(dirty checking)**: 트랜잭션 안에서 엔티티 값만 바꾸면 `save()` 없이 UPDATE 실행
  - `@Transactional(readOnly = true)`를 클래스에, 쓰기 메서드만 `@Transactional`
- `SeriesController`: GET(목록, `?active=` 필터) / POST / PUT / PATCH(사용 여부)
- Postman으로 등록·중복·빈 값·수정·사용 중지·없는 ID까지 상태 코드 확인
- 데모 데이터: 가상 브랜드 5개 등록 후 SQL `UPDATE ... CASE`로 영어 이름 일괄 변경
  - SQL로 직접 바꾸면 JPA Auditing이 동작하지 않아 `updated_at = NOW(6)`을 직접 지정

### 2. 관리자 로그인 (Spring Security 세션)
- `Admin` 엔티티: Lombok `@Builder`로 생성자 생략, `@Enumerated(EnumType.STRING)`으로 역할 저장
- `AdminInitializer`: 앱 시작 시 관리자가 없으면 `.env` 정보로 SUPER_ADMIN 자동 생성 (BCrypt 암호화)
- `SecurityConfig`: **formLogin**으로 로그인/로그아웃을 직접 구현하지 않고 처리
  - 로그인은 `x-www-form-urlencoded` 형식으로 받음 (JSON 아님)
  - 미로그인 요청은 로그인 페이지 대신 **401** 응답 (`HttpStatusEntryPoint`)
  - 로그인 성공 시 `last_login_at` 기록, 비활성 계정 로그인 차단
- `/api/auth/me`: 새로고침 후 로그인 상태·역할 확인용

### 3. 역할별 권한 (본사 SUPER_ADMIN / 대리업자 ADMIN)
- 상품·시리즈·증정 규칙·구매사이트: 조회는 모두, 등록·수정·삭제는 SUPER_ADMIN
- 관리자 계정·활동 로그 API: SUPER_ADMIN 전용
- `requestMatchers`는 **위에서부터 먼저 맞는 규칙**이 적용됨 (GET 허용 규칙을 먼저 둠)
- 화면에서 버튼을 숨겨도 주소로 직접 요청할 수 있으므로 **서버에서 막는 게 실제 보안**

### 4. 설계 변경 (ERD)
- 특전을 상품 테이블에 합침 (`item_kind`: GOODS / SPECIAL_GIFT) → 판매·증정 모두 같은 재고 사용
- 증정 시 입고수량에서 차감, 재고 = 입고수량 - 판매량
- 구매·입고 테이블 제거 → 상품에 구매사이트·구매일·입고일 컬럼으로 관리
- 증정 규칙을 2가지로 단순화: 금액 구간별 증정(개수, 대상) / 15만 원 이상 무료배송
- 공동구매 주문서: 배송방법 추가, 2차금은 소수점 저장(`decimal(15,2)`)

### 🔧 해결한 에러

**1. `Invalid profile property value found in Environment under 'spring.profiles.active'`**
- 원인: IntelliJ **활성 프로필** 칸에 `-Dspring.profiles.active=demo`를 통째로 입력 → IntelliJ가 앞에 옵션을 한 번 더 붙여서 프로필 이름이 `Dspring.profiles.active=demo`가 됨
- 해결: 활성 프로필 칸에는 **`demo`만** 입력

**2. `Access denied for user 'invento_app'@'localhost' (using password: YES)`**
- 원인: IntelliJ를 `Invento` 루트 폴더로 다시 열면서 **작업 디렉터리가 `backend` → `Invento`로 바뀜** → `optional:file:.env`가 `.env`를 못 찾고, 비밀번호 자리에 `${DB_PASSWORD}` 글자가 그대로 들어감
- 해결: `.env`를 루트로 옮기고, 실행 위치와 상관없이 찾도록 두 경로 모두 지정
  ```yaml
  spring.config.import: optional:file:.env[.properties],optional:file:../.env[.properties]
  ```

**3. 세션 쿠키 `SameSite` 설정이 적용되지 않음**
- 원인: `server.servlet.session.cookie.same-site`를 `spring:` 아래에 넣어서 `spring.server...`라는 존재하지 않는 설정이 됨
- 해결: `server:`를 YAML 최상위로 이동 (설정 키의 들여쓰기 위치가 곧 설정 이름)
